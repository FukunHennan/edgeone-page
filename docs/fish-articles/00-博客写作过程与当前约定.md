# 《Fish 机器鱼平台的搭建流程》写作过程与当前约定

本文用于个人博客发表。这里记录与作者逐步讨论后确认的写作方向，供后续修改章节时回看。`01-需求理解.md` 保存此前站点初稿的要求和修订历史；两者不一致时，以本文件及作者后续确认为准。

## 这次写作如何形成

1. **确定用途与重点。** 文章先说明平台的目的和功能，再按开发过程介绍技术选择。作者希望它能为以后继续开发提供技术提醒，重点包括公网接入、实时视频、前后端选型、网页与 ESP32 通讯，以及赛事画面的直播、录制、回放和下载。
2. **确定表达方式。** 作者认为原稿文字过多、偏口语化；正文应多用架构图、流程图和表格，让每张图说明一个问题。文章不放具体项目效果图片，读者通过 GitHub 查看源码和界面。不设“本机运行”“进展与验证边界”等章节。
3. **按开发顺序定提纲。** 在功能介绍后，依次写技术选型、设备通讯、公网接入、视频路径、赛事画面。逐章确认，再合并成博客正文。
4. **核对技术事实。** 使用 Fish 仓库固定提交 `134699900e14ad2cbe6eeb0878e1dc55431ceab5` 核实当前实现；源码能说明程序如何工作，不能代替作者说明当时遇到的问题和选型动机。
5. **核实问题与选型依据。** 第三章初稿从网络原理推断作者的问题，被作者纠正。作者确认：有长期域名，但没有可用于对外提供服务的公网 IP，外网设备无法访问网页和实时视频；网页选择 Cloudflare Tunnel，视频尝试直连或 TURN；项目当时处于试验阶段，也希望观察 TURN 的中转效果。因此章节改按“问题背景 → 方案选择 → 选择依据”展开。
6. **统一技术博客语气。** 作者要求减少口语化表达。已写章节采用准确、克制的技术叙述；保留真实开发动机，但不使用聊天式标题或未经证实的效果描述。
7. **区分两条传输路径。** 作者要求分别说明前端访问与视频传输。第三章聚焦浏览器通过域名、Cloudflare Tunnel 访问 Go 的页面、接口和控制连接；第四章聚焦视频媒体的直连、TURN 与 JPEG 快照降级。WebRTC 信令走前端接口路径，不等于媒体画面走 Tunnel。
8. **补全赛事画面链路。** 第五章区分直播媒体与主机端录像；作者确认录像、回放和下载主要用于完善系统，并支持赛后复盘、争议核查及资料留存。摄像头通过 USB 连接 Fish 主机，录像直接使用主机上的画面源；不虚构对浏览器录屏方案的历史比较。

## 已由作者确认的经历与边界

- Go：作者当时正在学习 Go，想尝试服务器开发，此前缺少同类项目经验。
- Python：已有可用的视频工具，因而沿用 Python 处理相机与视频。
- 前端：作者此前没有前后端项目经验，初始技术选择主要参考 AI 建议；现有前端的样式维护和加载体验是需要如实讨论的问题，不在无测量时指定慢的原因。
- 公网接入：作者有长期域名，但没有可用于对外提供服务的公网 IP；选择 Cloudflare Tunnel 作为网页入口。
- 视频：作者选择尝试直连或 TURN，并希望在试验阶段观察 TURN 中转效果。当前代码的失败顺序与正在开发的自动最优路径切换应分开表述，不能把后者写成已经完成。
- 视频路径的新增经历：外网访问端当时无法直接访问运行 Go/Python 视频服务的 Fish 主机；这里的“设备”不是 ESP32。快照用于作为尽可能稳定的最终兜底；这是选型目标，不是经实测证明的稳定性保证。
- “是否局域网”的判断对象是访问者 PC 与 Fish 服务器。当前程序以 WebRTC 连通和画面到达情况判断直连可用性；IP 比较可作为技术讨论，但没有参与当前选路。
- 前端访问路径承载页面、静态资源、HTTP 接口及控制 WebSocket；WebRTC offer/answer 信令通过 HTTP 接口交换。正常视频媒体走浏览器与 Python 的直连或 TURN，中断降级后的 JPEG 快照才经 Go 的同源 WebSocket。两条路径不可混写。
- 赛事画面：直播与服务器录像共用处理后的选手画面源，但输出链路不同。作者确认录制目的与 USB 摄像头位于主机这一选型依据；回放、下载、时间轴和录像启停的细节以固定版本源码核实。

## 后续写作方法

- 写个人开发经历时，先核实问题、选择和当时原因；证据不足就向作者问，不从代码倒推作者意图。
- 标题和正文使用专业、平实的书面表达；用“问题背景、方案选择、选择依据”等结构呈现开发经历，避免聊天式设问与主观夸饰。
- 图表承载结构和流程，文字解释决策理由、关键技术和实施提醒。先用源码或权威文档核对技术结论；公开正文只保留少量官网文档链接，不放项目源码文件链接。源码核对依据保留在逐章草稿中，避免正文随仓库文件调整而产生大量失效链接。未实测的效果不写成结论。
- 2026 年 10 月的中文版小修：标题保留“搭建流程”，开头补五步路线；前端建议明确标为事后判断；删去与视频路径图重复的表格，保留作者确认的 TURN 试验动机；放大中文版流程图文字。正文用月份限定“当前实现”。作者确认中文版暂无问题后，再据此完成英文版。
- 五章草稿已合并为 [中文版合稿](08-合并稿-中文.md)，放入 `source/zh-CN/_posts/fish-robot-platform.md`；对应的 [英文合稿](09-merged-draft-en.md) 放入 `source/en/_posts/fish-robot-platform.md`。两版保留相同章节、九张对应图表及六条官网文档链接，本地构建与预览已检查。
- 本文件记录过程，不代表已发布。更新博客正文、提交或发布时分别检查实际状态。
