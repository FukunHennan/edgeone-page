## 当前目标

以 Fish 为首个样例，写面向项目访客、兼顾后续开发回查的技术文章。重点回答问题如何拆解、技术如何分工、请求和状态如何流转、失败时怎样处理，以及修改关键路径时应核对什么。用架构、流程与设计对照图说明整体关系，正文深入解释关键机制与源码依据。文章不展示具体项目效果图或界面截图；具体源码和界面通过 GitHub 仓库查看。中英文同步，保留文章地址、入口和发布状态。

- P0：问题与约束 → 技术栈职责 → 架构及通信 → 指令生命周期 → 赛事状态 → 设备认证、控制归属与 OTA；不设置本机运行、进展或验证边界章节。
- P0：用真实依赖文件说明 Go、React、Vite、Python 相机/视频生态、Arduino/PlatformIO、WebSocket/JSON 的作用；避免只列名词。
- P0：保留技术职责、系统架构、运动指令、赛事协作和关键校验五类方案图，双语图源可编辑。
- P0：正文和项目卡片均不使用界面或运行效果截图；卡片可以使用方案图作为封面，GitHub 链接保持可访问。
- P0：设计理由表述为基于实现的分析，不虚构作者历史决策、备选方案实验或性能优势。
- P0：关键技术说明附固定版本源码链接，区分设备认证与账号授权、STOP 与断电、直播与录像、文件摘要与构建指纹。
- P1：同步项目卡片摘要和公网专题的链路描述。
- P2：实测结果待有证据时补充，个人贡献待明确范围后表述。
